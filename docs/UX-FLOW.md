# 0.4.0 连续触控与语音

用户要求：保持在触控页面，连续说话和发送，不反复返回；Mac 默认接收。沿用深色背景、浅绿提示、原生控件，不扩大到新语音 SDK 或录音权限。

| 操作 | 旧流程（用户反馈/代码推断） | 当前设计（待真机验收） |
| --- | --- | --- |
| 开始一次会话 | 连接、开始、打开文字页面或面板 | 点开始，自动连接上次 Mac，输入区随触控页出现 |
| 发下一句话 | 发送后再次展开面板/键盘 | 留在当前输入区，继续用输入法语音、发送 |
| 重复发送的页面切换 | 0.3.0 每轮往返 2 次；0.3.1 每次收起后需再次打开 | 0 次；发送不收起面板/键盘 |
| Mac 接收 | 打开应用后还需点开始接收 | 启动即接收，登录启动配置一次 |
| 全黑和语音 | 发送后自动收起 | 用户主动打开/恢复全黑，发送不擅自改变状态 |

竖屏：顶部退出/纯黑，触控区居中，下方输入区和键盘。
横屏：左侧触控、右侧输入，隐藏额外标题腾出空间。

只清除已确认收到且仍与原稿一致的前缀；用户传输期间追加或修改的内容保留。不会自动按回车提交给 Agent。豆包输入法自身的语音按钮仍需用户点击；本应用没有公开接口能保证替用户启动豆包录音。

验收以实际画面和连续发送为准，编译通过不能替代布局检查。

当前未取得 0.4.0 真机布局截图，未做独立视觉评审；待覆盖安装后检查键盘展开的竖屏/横屏代表画面。
